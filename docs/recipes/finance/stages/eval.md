## prepare_data

**File:** `nvflow/recipes/finance/stages/evaluation/prepare_data.py`
**Registry:** `recipe="finance"`, `workflow="eval"`, `stage="prepare_data"`

### Purpose

Download and prepare benchmark datasets for evaluation. Fetches SEC-QUE, FinanceBench, and finance_agent datasets and formats them for the evaluation pipeline.

### Inputs

| Parameter | Type | Description | Default |
|-----------|------|-------------|---------|
| `dataset_names` | list | Benchmark names to prepare (e.g., ["secque", "financebench"]) | Required |
| `output_dir` | path | Directory to save prepared datasets | Required |

> **Note:** Use `dataset_names` (not `benchmarks`). Do not include `:N` notation here - that's for evaluation stages.

### Supported Benchmarks

**SEC-QUE** (565 samples):
- **Analysis** (72): Qualitative analysis of financial information
- **Comparison** (220): Cross-company or temporal comparisons
- **Ratio** (188): Financial ratio calculations and interpretation
- **Risk** (85): Risk factor identification and analysis

**FinanceBench** (150 samples):
- **metrics-generated** (50): Standardized financial metrics
- **domain-relevant** (50): Domain-specific financial questions
- **novel-generated** (50): Novel question generation

### Resources

- **Compute:** CPU only (HuggingFace download + format conversion)
- **Runtime:** ~3 min (downloads both benchmarks, caches for future runs)

## Baseline Model Stages

These stages evaluate baseline (non-fine-tuned) models. They are registered under `workflow="eval"` and run via `eval/baselines.yaml`.

Stages are auto-generated by `WorkflowRunner._expand_dynamic_stages()` from the `models` section in `baselines.yaml`.

### Available Baselines

| Stage | Model | GPUs |
|-------|-------|------|
| `qwen3-4b` | Qwen3-4B | 1 |
| `qwen3-14b` | Qwen3-14B | 1 |
| `qwen3-32b` | Qwen3-32B | 2 |
| `gpt-oss-120b` | GPT-OSS-120B | 2 |
| `nemotron-nano-9b-v2` | Nemotron-Nano-9B-v2 | 1 |
| `nemotron-3-nano-30b` | Nemotron-3-Nano-30B | 2 |

### Usage

```bash
# All baselines
uv run nflow run-all --config nvflow/recipes/finance/workflows/eval/baselines.yaml

# Specific baseline
uv run nflow run gpt-oss-120b --config nvflow/recipes/finance/workflows/eval/baselines.yaml
```

## Embedded Eval Stage

**File:** `nvflow/recipes/finance/stages/evaluation/evaluate.py`
**Class:** `EmbeddedEvalStage`
**Registry:** `recipe="finance"`, `workflow="sft"`, `stage="eval"` and `recipe="finance"`, `workflow="grpo"`, `stage="eval"`

### Purpose

Evaluates training checkpoints at specified steps, embedded as the last stage of SFT and GRPO training pipelines. Loads shared settings (benchmarks, judges, datasets) from `eval/base.yaml` at runtime.

### Configuration (in training YAMLs)

```yaml
stages:
  eval:
    eval_steps: [2600, 5000, 7408]
    checkpoint_path: ${directories.step-4-training}/model-name
    format: megatron        # Match the checkpoint's training backend: "fsdp" or "megatron"
    baseline_model: /hf_models/Qwen/Qwen3-14B
    server_type: vllm
    gpus: 1
    inference_args: >-
      ++prompt_config=nvflow/recipes/finance/prompts/secque_template.yaml
      ++inference.temperature=0.6
    server_args: "--max-model-len 40960 --async-scheduling --reasoning-parser qwen3"
```

### Parameters

| Parameter | Type | Description |
|-----------|------|-------------|
| `eval_steps` | list[int] | Training steps to evaluate |
| `checkpoint_path` | path | Base path to training checkpoints |
| `format` | str | Must match the checkpoint's training backend: `"megatron"` (SFT, finance_sec_search GRPO, production) or `"fsdp"` (equivalence_llm_judge GRPO demo); `"hf"` for HF checkpoints |
| `baseline_model` | path | HF model path for baseline comparison |
| `server_type` | str | Inference server: `"vllm"`, `"openai"` |
| `gpus` | int | GPUs for model server |
| `inference_args` | str | nemo-skills inference arguments |
| `server_args` | str | vLLM server arguments |

### Behavior

1. For each step in `eval_steps`:
   - **HF format**: Constructs model path as `{checkpoint_path}/step_{N}/policy/`
   - **Megatron format**: Submits conversion job, then evaluates converted HF model
2. Evaluates the `baseline_model` for comparison
3. Skips benchmarks that already have `metrics.json` results

### Output Structure

```
${base_output_dir}/eval/
├── step-2600/
│   └── eval-results/{benchmark}/metrics.json
├── step-5000/
│   └── eval-results/{benchmark}/metrics.json
├── step-7408/
│   └── eval-results/{benchmark}/metrics.json
└── baseline/
    └── eval-results/{benchmark}/metrics.json
```

## Common Evaluation Parameters

All evaluation stages use the `nemo-skills` evaluation API with these parameters:

### Core Configuration

| Parameter | Type | Description |
|-----------|------|-------------|
| `output_dir` | path | Directory for evaluation results and logs |
| `benchmarks` | list | Benchmarks to evaluate (e.g., ["secque:5", "financebench:5"]) |
| `datasets_dir` | path | Directory containing prepared datasets from prepare_data |

### Judge Configuration (`judge`)

| Parameter | Description |
|-----------|-------------|
| `model` | Judge model for scoring (e.g., "gpt-5-chat-latest") |
| `server_type` | Judge server type: "openai", "vllm" |
| `server_address` | Judge API endpoint (for external APIs) |
| `extra_args` | Judge-specific arguments (prompt_config, temperature=0.0, etc.) |

## Metrics

The evaluation pipeline computes multiple metrics per benchmark, aggregated across seeds.

### Primary Metrics

- **pass@1 (judge_correct)**: Percentage of examples judged correct by GPT-5 (primary metric)
- **predicted_answer_ids**: Number of examples with valid answer extraction
- **missing_answers**: Number of examples with no answer extracted

### Production Results (SEC-QUE Benchmark)

| Model | judge_correct | Notes |
|-------|---------------|-------|
| **Baselines:** | | |
| Qwen3-14B | 59.7% | Baseline model |
| Qwen3-32B | 61.8% | Larger baseline |
| GPT-OSS-120B | 61.9% | Best baseline |
| Nemotron-Nano-9B-v2 | 46.8% | Smaller model |
| **Fine-tuned (Qwen3-14B-48k):** | | |
| Step 2600 | 70.3% | +10.6% vs baseline (end of epoch 1) |
| Step 5000 | 70.3% | Mid-training |
| Step 7408 | 71.0% | +11.3% vs baseline (final) |

## Common Issues

### Checkpoint Conversion Failures

**Symptom:** Conversion job fails or HF model not created

**Solutions:**
- Check Megatron checkpoint exists at specified path
- Verify `baseline_model` path is correct
- Check conversion logs
- Ensure `conversion.num_gpus` matches training GPU count

### Low judge_correct Scores

**Check:**
- **Prompt template**: Verify `prompt_config` matches model's expected format
- **Answer extraction**: Check `predicted_answer_ids` vs `num_entries` in metrics
- **Judge prompt**: Ensure `sec_judge.yaml` is appropriate for domain
- **Inference params**: Temperature too high (> 0.8) causes inconsistency

### vLLM Server Crashes / OOM

**Solutions:**
- Reduce `--max-model-len` in `server_args`
- Increase `gpus` for larger models
- Check GPU memory: 40GB+ required for 14B models with long context
